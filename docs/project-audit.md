### 已实施的修复与优化

1. **补全媒体结果恢复。** 原队列启动恢复只枚举 `result-N.png`，已落盘的 GIF、JPEG、WebP 收据会被误判为中断。
   新增 `lib/reply-assets.cjs`，供上传、恢复和 QQ 回传共用 MIME/文件名规则。恢复从实际字节确定格式，校验大小、基础结构、
   连续序号、普通文件和唯一版本；缺失、错格式、同序号多版本或符号链接保持中断，不猜测文件、不重新生成。
   先复现失败再修复，保留旧 PNG 收据兼容；图片字节不改写。
2. **统一原子落盘。** JSON、预设、回复文本、网页媒体和本地历史图片复用 `writeAtomic`。
   使用唯一暂存文件和独占创建，失败保留旧文件并清理暂存；避免多个固定 `.tmp` 实现分散维护。
3. **任务查询建索引。** 编号、平台消息去重和最近任务使用 Map；忙状态和调度只扫描少量待处理任务。
   索引引用原任务，不复制任务快照；成功入队后建立索引，清理后重建，保留用户/聊天/会话隔离。
   保留期清理由反复 `indexOf/splice` 改为一次筛选；磁盘失败恢复后的终态任务不会占用错误的忙状态或容量。
4. **拆出 QQ 发送职责并解耦执行槽。** `bridge/qq-delivery.cjs` 负责确认超时、媒体编码、发送游标、重发和发送锁；
   通过 `save/status` 回调与队列协作。结果先持久化，再释放生成槽，慢速 QQ 上传不阻塞下一条生成。
   生成仍严格串行；成功回复按聊天串行，跨聊天可以独立进行，同一回复的片段不会被其他成功回复穿插。
   进度和失败提示仍即时发送，不纳入成功回复流的排序。
   旧任务的发送回调结束时不会误释放新任务的执行槽。
5. **关闭与取消不留下悬挂状态。** 网页连接器在执行进度回调前注册取消监听和计时器，回调取消立即生效；
   会话绑定回调关闭服务后不创建新的任务。QQ 关闭后停止后续片段和排队回传，保留已经确认的游标；
   已交给 QQ 的在途请求仍可能完成，不声称能够撤销。
6. **下载共用一个超时预算。** DNS、重定向、连接和响应体共用整次图片下载的时间上限，
   不再每跳重新开始计时，避免任务尚未入队就耗尽 QQ 被动回复窗口。原 DNS 固定、地址、大小和格式检查保留。
7. **本地图片缓存限于单次请求。** 重复历史图片在一次请求中只读、校验和编码一次；仍逐次验证元数据，
   下一条请求重新校验磁盘，修改或缺失的历史图片不会被跨请求缓存掩盖。非 JSON 的 401/403 仍报告认证错误。
8. **清理无使用路径与重复工作。** 删除仅测试引用的 `textOf/textLength`、无人读取的网页排队计数和 HTTP 成功检查重复分支。
   空闲扩展保留心跳，只在状态改变时写 `chrome.storage.local`，避免同一空闲状态每两秒持久化一次。
9. **现场修复中文下载标签。** 实测正文标签「下载工程验收红蓝.gif」与预览卡片「工程验收红蓝.gif」被当成两个文件，
   自动点错控件后等待预览超时。仅在同一 assistant 回复内存在唯一对应预览时去掉下载操作标签，并优先保留真实文件名的精确匹配；
   真正以「下载」开头的文件名不改写。回归验证去重、使用正确预览按钮和 GIF 原始字节读取。

### 性能证据

`npm run benchmark:queue` 使用 10,000 条终态任务，每项每组 1,000 次查询，先预热 2 组再取 5 组中位数；
同时消费查询结果，比较优化前算法和当前实现的结果校验和。此次本机测得：

- 按编号查询：57.760 ms → 0.032 ms。
- 当前会话最近任务：68.068 ms → 0.067 ms。
- 平台消息去重：4.275 ms → 0.086 ms。

这是内存元数据查询基准，不包含任务加载、磁盘 I/O、模型、图片上传或 QQ 网络耗时，不代表端到端响应加速倍率。
默认永久保留历史的策略不变；大量历史仍有启动读盘和内存成本，索引不能消除这些成本。

## 修复与优化

1. **配置在启动前完整校验。** 抽出 `core/config.cjs`，避免字符串名单被拆成字符、错误布尔值静默生效、非法端口或负保留天数进入运行时；限制计时器到 Node 支持的整数范围。
2. **会话变更在落盘成功后发布。** 新建/切换/改名/关闭/绑定失败不再污染内存。重开通过一次提交完成关闭和替换，保留当前任务持有的会话引用。
3. **复用原子 JSON 写入。** `lib/state.cjs` 供会话、偏好、队列和结果收据使用；失败清理暂存文件并保留原状态。
4. **连接诊断与任务心跳分开。** 新增 `桥接连接`、`GET /health`、`npm run doctor`。诊断不创建消息任务，不刷新浏览器在线时间；此前任何带令牌请求都能把离线浏览器标为在线。
5. **回复字符与围栏正确截断。** Emoji 不再被总量截断切成半个字符；包含反引号围栏的代码使用更长外层围栏；结构化代码截断保留闭合围栏；段间分隔符也计入预算。极小消息限额下，先省略无法容纳的语言标签，围栏自身仍无法容纳时改为 Markdown 缩进代码，避免拆出半个围栏。
6. **故障回报保持终态。** 扩展先持久化 `failing` 及原始诊断，再重试本机回报；连接恢复后不重新上传、填写或提交。
7. **已有草稿与附件不混入请求。** 开始准备任务前检查既有内容，上传操作再检查一次；保留页面并提示清理。
8. **生成状态只读取状态控件。** 回复正文中的“正在生成 / Thinking / Generating”不会让完成的内容多等待四分钟。
9. **段内图文顺序与直接文本不丢失。** DOM 读取保留图片前后文本的实际顺序，不再把图片统一移到段尾。
10. **生命周期失败明确结束。** 关闭服务后不再创建等待中的任务；网页会话绑定落盘失败立即终止，避免丢掉绑定后空等超时。
11. **扩展职责拆分。** `background.js` 管理状态机，`bridge-client.js` 管理本机 HTTP，`page.js` 管理注入页面逻辑；整体 worker 回归仍从真实入口加载。
12. **验证入口便于扩展。** 测试文件由启动器显式发现，Node 20+ / Windows 无须 glob；新增语法、版本、入口与扩展导入检查，接入 CI。
13. **适配实际网页的代码与表格结构。** 现场发现 CodeSurface 的语言标签在独立头部，现从结构化头部提取，过滤复制/换行等控件；表格包含合法 Markdown 表头分隔行。
14. **纯图片轮次参与用户消息定位。** 现场发现附件轮次没有文字气泡，现合并有明确 user 标记的搜索单元，按 DOM 顺序定位并去重容器及气泡，避免漏确认或把旧回复混入本轮。

会话残留、Emoji/围栏、既有输入、故障重试、正文误判、图文顺序、关闭竞态和绑定失败均先以失败测试复现，再修复为通过。

`pageStep` 被序列化后注入网页，其 DOM 辅助函数必须位于函数内部。只有本机 HTTP 回传可以自动重试，网页发送点击不得盲重试。新增持久化字段需要同时考虑中断记录和 `result.json` 收据。修改协议时同步插件和扩展版本，并在现场核对两边都完成重载。
