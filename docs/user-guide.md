# 使用手册

完整功能、命令参数和进阶配置。首次安装请先阅读[安装说明](installation.md)。

### 本地技能库

支持读取 `技能名/SKILL.md` 作为技能目录。工作模式通过原生 **@技能** 调用网页已安装技能；
LM Studio 使用本机技能正文作为系统提示词。更新后重启 Koishi，并在 Chrome 扩展页重新加载本扩展。
在 QQ 私聊发送（群聊需 @ 机器人）：

```text
/skill
/skill show summarize-text
/skill summarize-text
请整理下面的讨论记录：……
/skill off
```

- `/skill` 或 `/skill list [页码]`：查看当前选择、技能名称和说明。
- `/skill 名称`：选择当前会话的一个技能，从下一条消息起生效。
- `/skill show [名称]`：查看技能指令；不带名称时查看当前技能。长正文用 `/skill show --page 2 [名称]` 翻页。
- `/skill off`：后续消息不再选择技能。已有聊天历史保留；
  需要空白上下文时，先关闭或切换技能，再 `/new`。

默认库为 `data/skills/`（随 `dataDir` 调整），首次创建目录时放入 `examples/skills/` 中的示例：
文本整理 `summarize-text` 和日系写实人像 `chatgpt-jp-portrait`。
本机新增或修改技能，下次查看和发消息即读取最新内容，无需重启。
重启不会覆盖本地修改或恢复已删除的示例；已存在的空目录不会自动安装示例。

每个技能使用独立目录，例如 `data/skills/translate-text/SKILL.md`：

```markdown
---
name: translate-text
description: 翻译用户提供的文本，保留术语、数值与原文格式。
---

按用户指定的目标语言翻译本次文本。没有指定目标语言时先确认。
保留人名、数值、代码和专有名词；不确定的术语标出原文。
```

`name` 必须与目录名一致，最多 64 字，只含小写字母、数字和连字符；`list/show/off` 等为保留名称。
`description` 最多 1000 字，正文最多 24000 字。文件为 UTF-8，文件头的 `name/description` 支持普通文本、
单/双引号文本和 `>`/`|` 多行说明；复杂 YAML 标记、锚点等不支持。其他文件头字段不会授予工具权限。
目录及 `SKILL.md` 均须为普通目录/文件，符号链接不加载。无效技能会在列表中提示，用 `show 名称` 查看具体错误。

已有技能库可通过 `skillsDir: /绝对路径/skills` 接入；配置目录必须已存在，插件只读，不向其中安装示例或修改文件。
也可将需要的技能目录复制到 `data/skills/`。没有配置时只读取本项目数据目录，不自动扫描用户级技能库。
库中的技能说明和正文可由所有获准使用机器人的用户查看；使用 LM Studio 时正文会提交给本地模型，管理员应选择适合共享的技能。

选择按用户、私聊/群聊、会话和模式隔离，重启后保留。工作和本地模型分别选择技能；聊天模式不调用技能。`/new` 沿用设置，`/chat` 恢复对应会话。
处理中可以查看技能，切换或关闭需等待完成或先 `/stop`。入队时保存正文和版本摘要，之后编辑、删除文件不会改变已有任务；
选中技能丢失或无效时明确报错。`/status` 显示当前选择，`/retry` 仍只重发已有结果。

网页端先输入 `@`，在原生菜单中选中技能，确认技能标记后再发送用户原文，**不会把 SKILL.md 拼进文本框**。
网页账号须已安装同名技能：例如本地 `chatgpt-jp-portrait` 对应菜单中的 `chatgpt jp portrait`；空格与连字符等价。
找不到、同名结果不唯一或技能标记失效时停止发送并报告原因，不自动改为粘贴技能正文。
本机文件用于列表和选择；网页实际执行的规则与版本由网页已安装的技能决定，本机编辑不会自动同步到网页。
LM Studio 把技能正文与角色预设合并为系统提示词，
历史只保存原始用户输入。预设、技能及本次消息共同占用 `lmStudioHistoryChars`，超限会在提交前报错。
普通消息、图片/引用消息和 `/draw` 均沿用原有流程；启用的技能也会作用于 `/draw`。

本地接入只加载 `SKILL.md` 文本，不执行本机技能里的脚本、CLI、MCP 工具，也不自动加载 `references/` 或 `assets/`。
网页原生技能使用 ChatGPT 自身提供的能力；它不会因此获得对本机项目目录的访问权限。

#### 日系写实人像技能

`chatgpt-jp-portrait` 从本机 `Agent-Skill/skills/chatgpt-jp-portrait` 导入，已将其
`assets/chatgpt-web-instructions.md` 的完整动作表、镜头表和改图规则内嵌到桥接版 `SKILL.md`，
供本地模型直接加载，无需模型读取本机文件。网页模式调用你已导入的原生技能。
`examples/skills/chatgpt-jp-portrait/SOURCE.json` 保存来源文件和导入内容的 SHA-256。
新增安装自动提供该技能；已有技能目录时，将 `examples/skills/chatgpt-jp-portrait/` 复制到实际 `dataDir/skills/`，不要覆盖已有同名修改。

QQ 使用示例（每行分别发送，群聊需 @ 机器人）：

```text
/mode 工作
/skill @chatgpt jp portrait
J01，P02，F01，奶油色针织衫，樱花街角，直接出图。
把刚才的针织衫改成浅蓝色，人物、动作和背景保持，直接改图。
P03 + C04，白色陶瓷杯、浅粉针织袖口，只要手部特写提示词。
```

默认主体为虚构的18岁成年女性，可明确指定其他成年年龄。`P02` 为回头微笑，`F01` 为腰部以上半身，
`P03 + C04` 为捧杯的手部特写。网页生成图片；LM Studio 只输出文字提示词。技能不保证每次出图或人脸完全一致。

`/skill chatgpt-jp-portrait` 也可选择同一个技能。选一次后，后续消息会自动带上原生技能标记。
原生技能需要“工作”模式；`/skill 名称` 会自动进入工作模式，使用独立网页会话。
原生菜单选择时会短暂激活 Chrome 窗口和独立标签页，选好后恢复之前的焦点。
选择期间请保持电脑解锁；手动切换窗口或标签页会停止本次选择。

`npm run validate:portrait` 使用当前 Chrome 扩展及真实 ChatGPT 网页，验证选择技能、仅提示词、出图、同一网页会话改图，
并逐字节核对隔离模拟 QQ 回传的图片。它不向真实 QQ 联系人发消息，也不读取现有聊天状态。
运行前需先停止占用桥接端口的 Koishi 实例，运行后恢复实例；默认复用 `data/web-bridge-token` 和端口 5141，
可用 `WEB_BRIDGE_PORT` 指定与扩展一致的端口。测试记录、原始图片和回复保存在 `data/acceptance/portrait-*/`。
若前两步已通过、改图明确返回网页图像服务错误，可用
`npm run validate:portrait -- --resume data/acceptance/portrait-目录` 在同一会话额外重试改图一次，保留原错误与已通过结果。

### 图片提示词模板

模板是保存在本地的 UTF-8 Markdown 文本，适用于 ChatGPT 网页生图。
重启 Koishi 加载更新后，首次创建模板目录时会自动放入「角色海报」「角色适配海报」「参考画面换角色」示例。
在 QQ 私聊分别发送以下命令（群聊需 @ 机器人）：

```text
/prompt
/prompt 角色海报
/prompt preview 孙悟空
/draw 孙悟空
```

- `/prompt` 或 `/prompt list [页码]`：查看当前选择和模板列表。
- `/prompt 模板名`：选择模板，名称不带 `.md`，可包含中文和空格。
- `/prompt show [模板名]`：查看原文，不指定名称则查看当前模板。
- `/prompt preview 角色名`：只预览替换后的完整文本，不请求 GPT。
  长正文分页；`/prompt show --page 2 [模板名]` 和 `/prompt preview --page 2 角色名` 查看后续页。
- `/draw 角色名`：使用当前模板，把所有 `{{角色名}}` 替换为输入的角色名，将展开后的文本直接作为一条消息发送给 GPT。
  模板原文不会被修改，也不会增加一轮模型调用来润色提示词。
- `/prompt off`：取消当前模板选择；普通聊天本来就不套用模板，发「把背景改成蓝色」仍可接着改图。

模板默认位于 `data/prompts/`；自定义 `dataDir` 时使用该数据目录下的 `prompts/`。
所有获准使用机器人的用户均可在 QQ 创建、查看和选择公共图片模板，只有创建者可在 QQ 编辑、删除自己的模板，权限与 `/preset` 一致。
创建时，将下面整段作为**一条 QQ 消息**发送（群聊需 @ 机器人）：

```text
/prompt create 水彩肖像
请生成一张以「{{角色名}}」为主角的水彩肖像。
保留角色的标志性外貌和服装，背景简洁，柔和自然光，竖版构图。
```

创建不会自动选择模板；发送 `/prompt 水彩肖像` 后即可用 `/draw 角色名` 生成。
编辑时发送 `/prompt edit 水彩肖像`，从下一行开始填写**完整的新正文**，整段作为一条消息发送；
删除使用 `/prompt delete 水彩肖像`。编辑后的内容在下一次预览或 `/draw` 时生效，已入队任务保持原版本。
删除保留聊天历史与任务；选择了被删模板的会话需重新选择模板或 `/prompt off`。
`/prompt` 和 `/prompt show 模板名` 标注「我创建」或公共/本地模板属性，不公开其他用户的 QQ 标识。

在本机添加、编辑、重命名或删除 `.md` 文件即可管理模板，下次查看或发送时读取最新内容，无需重启。
QQ 创建的文件首行注释记录创建者，本地编辑时保留该首行；管理注释不出现在预览、GPT 请求或任务快照中。
没有创建者注释的本地及内置模板公共可选，但只能在本机编辑或删除；可用新名称在 QQ 创建自己的版本。
例如创建 `data/prompts/水彩肖像.md`，正文为：

```text
请生成一张以「{{角色名}}」为主角的水彩肖像。
保留角色的标志性外貌和服装，背景简洁，柔和自然光，竖版构图。
直接生成图片，不要只输出提示词。
```

随后发送 `/prompt 水彩肖像` 和 `/draw 角色名` 即可使用。正文就是发给 GPT 的内容，不需要 YAML 文件头。
旧模板仍可直接使用。模板须包含 `{{角色名}}`，还支持任意自定义变量：

| 写法 | 含义 |
| --- | --- |
| `{{角色名}}` | `/draw` 开头输入的角色名，必填 |
| `{{场景\|雨夜天宫}}` | 不传场景时使用默认值“雨夜天宫” |
| `{{动作}}` | 无默认值的自定义必填参数，缺失时提示补齐 |
| `{{备注\|}}` | 可选参数，默认空文本 |
| `{{补充要求\|无}}` | 可选的自由描述，可直接表达画面修改要求 |

每个模板最多 16 种占位符。变量名为 1–32 字的中文、字母、数字或下划线，不能以数字开头；
同一变量重复出现时，默认值写法须一致。角色名不支持默认值，补充要求即使没有占位符也可以传入。
角色名为 1–100 字的单行文本，可包含空格；角色名和参数整段合计最多 1000 字，模板原文及最终发送文本均最多 8000 字。
名称最多 64 字，不可含路径字符；list、show、preview、off、create、edit、delete 等是保留名称。
仅读取普通 `.md` 文件，不读取符号链接。模板库由整个实例共享，编辑和删除受创建者权限限制。

例如选择「角色适配海报」，以下两条命令分别用于预览和生成：

```text
/prompt 角色适配海报
/prompt preview 孙悟空 | 场景=雨夜天宫 | 动作=扛着金箍棒 | 补充要求=黑白水墨
/draw 孙悟空 | 场景=雨夜天宫 | 动作=扛着金箍棒 | 补充要求=黑白水墨
```

参数不跨请求记忆，下次只发 `/draw 孙悟空` 会重新使用模板默认值。未知参数、重复参数和缺失必填项均会报错，
不会忽略后继续生图。`|` 分隔参数，`=` 分隔参数名和值；内容需要竖线时写 `\|`，需要反斜杠时写 `\\`。
参数值可以包含 `=`。显式空值（如 `备注=`）用于清空可选变量，必填项不能留空。
模板默认值可以包含普通竖线，无需转义；不支持嵌套占位符，也不会递归解析用户输入。

显式传入的参数还会以“本次明确要求”附在消息末尾，说明它们优先于模板默认描述及参考画面的冲突细节。
`补充要求` 适用于所有模板，旧模板无需增加占位符就能使用 `/draw 孙悟空 | 补充要求=水彩画风`。
`/prompt show` 显示原始变量和规则；预览显示替换后的实际消息及明确要求，翻页命令会保留完整输入参数。

「角色适配海报」提供场景、动作、画风、比例的默认值，并区分默认保留项和角色适配项。
「参考画面换角色」提供一段原创精灵弓箭手的参考画面，要求 GPT 保留雨夜石桥、构图和光影，
根据目标角色调整外貌、服装与道具，避免只改名字却留下原角色的银发、尖耳和长弓。
这些规则以普通 Markdown 正文写入文件，可在本地编辑，也可替换为自己的参考提示词。
角色的语义适配由 GPT 在同一轮生图中完成；本地只展开变量，不增加模型改写轮次。
预览能核对实际发送的指令，不能预先保证 GPT 的角色理解与最终图像效果。

选择按用户、私聊/群聊和会话分别保存，重启后仍保留；`/new` 沿用模板选择，`/chat` 恢复对应会话的选择。
每次 `/draw` 都保存当时的模板、原始参数输入、用户明确填写的值、包含默认值的解析结果、版本摘要和实际发送文本，之后编辑或删除文件不会改变已入队任务。
预览不锁定版本，`/draw` 使用发送时的最新模板。选中的模板被删掉或无效时会报错，不会发送不完整内容。
示例只在首次创建目录时安装，重启不会覆盖本地修改或恢复已删除的模板；可从 `examples/prompts/` 手动复制恢复或添加新示例，已有同名文件应先备份。
本地模板及任务快照随 `data/` 被 Git 忽略。

此功能使用现有网页生成和图片回传流程，沿用 `/status`、`/stop`、`/retry`；`/retry` 只重发已有结果，不重新生成。
当前会话若选择了 LM Studio，`/draw` 会提示先用 `/mode 工作` 切回网页。
GPT 实际返回的文字或图片均按现有方式回传；模板不会保证模型一定返回图片。每次生成会进入当前网页聊天历史，
希望不受之前图片影响时，先用 `/new` 开启新会话。

### 本机 LM Studio

在 LM Studio 的 Developer 页面启动 API 服务，并准备一个聊天模型。默认连接
`http://127.0.0.1:1234/v1`，只允许本机回环地址；无需 Chrome 或 ChatGPT 登录。
重启 Koishi 实例加载本次更新后，在 QQ 私聊发送（群聊需 @ 机器人）：

```text
/mode 本地
你好
接着刚才的话题继续聊
```

- `/mode` 查看当前模式；`/mode 聊天`、`/mode 工作` 切回对应网页模式。
- `/model` 查看本机模型；`/skill` 选择本地文字规则，与工作模式的技能选择分别保存。
- 只有一个聊天模型时自动选择；有多个时发送 `/model 模型编号`，例如
  `/model google/gemma-4-31b`。嵌入模型用于向量计算，不用于聊天。
- 每个用户在每个私聊/群聊的会话拥有独立上下文；历史保存在 `data/lmstudio/`，重启后继续。
  `/new [名称]` 沿用本地后端和模型，开启空白上下文；`/chat` 可切回旧话题。
- 聊天、工作与本地的上下文分别保留，切换模式不会复制另一边的历史。更换本地模型也使用独立上下文。
- 本地接入支持文字、图片加文字、纯图片和引用消息中的图片。图片需视觉模型（如本机 Gemma 4 31B），
  插件先检查 LM Studio 报告的视觉能力；文字与图片按原顺序提交，图片随会话保存，后续文字提问仍带原图。
  本地模型返回文字，不能通过此接入生成图片。`/reasoning` 操作网页设置，本地模型使用 LM Studio 的设置。
- `/logs`、`/status`、`/stop`、`/retry` 沿用现有命令。`/stop` 中止 HTTP 请求并停止等待，服务端是否立即停止计算取决于 LM Studio；
  `/retry` 只重发已保存的结果，不再次调用模型。连接失败、超时或服务重启时不自动重新提交消息。
- 上下文默认最多保留最近 20 轮、合计 12000 字符；超出时按完整问答对移除最早历史。
- 历史图片默认最多 4 张、总计 20 MB（每次输入仍最多 2 张、每张 10 MB）；超出任一上下文上限时
  移除最早问答及其不再使用的图片。原图另存于会话目录，清理旧任务不会影响保留中的图片上下文。
  模型自己的 token 上限仍可能更小；遇到上下文超限可 `/new` 或调低 `lmStudioHistoryChars`。
  任务保留策略 `retentionDays` 不删除会话上下文。

可选配置：`lmStudioBaseUrl`、`lmStudioModel`、`lmStudioApiKey`（启用服务认证时）、
`lmStudioMaxTokens`（默认 2048）、`lmStudioHistoryTurns`（默认 20）、`lmStudioHistoryChars`（默认 12000）、
`lmStudioHistoryImages`（默认 4）、`lmStudioHistoryImageBytes`（默认 20 MB）。历史图片上限需容纳一次允许的最大输入；
提高 `maxInputImages` 或 `maxInputBytes` 时，未指定的历史图片默认上限会相应提高。
设置 `lmStudioModel` 可指定首次切换时的默认模型。完整示例见 `koishi.example.yml`。

运行 `npm run validate:lmstudio` 可通过真实本地模型验证插件消息流、两轮续聊和重启后上下文；
测试使用临时数据及模拟 QQ 发送，不向真实 QQ 用户发消息，也不改现有聊天。
`npm run validate:lmstudio -- --vision` 验证真实视觉模型：图片与文字输入、重启并清理任务后看原图续聊、
`/new` 图片上下文隔离。测试图和结果保存在打印出的临时目录中。

### 公共角色预设（0.3.10）

所有获准使用机器人的用户都可以在 QQ 创建、查看和选择公共预设，只有创建者能在 QQ 编辑、删除自己的预设。
公共预设库共享，聊天历史和当前选择仍按用户、私聊/群聊及会话隔离，不会因为选择同一个角色而共享对话。

创建时，将下面整段作为**一条 QQ 消息**发送：第一行是命令和名称，正文从第二行开始。

```text
/preset create 旅伴
你扮演边境城镇的向导艾琳，与用户进行连续的中文角色扮演。
保持角色口吻，通过动作和台词推进剧情，不替用户决定行动或内心想法。
```

创建不会自动改变当前会话选择。后续命令分别发送：

```text
/mode 本地
/preset 旅伴
/preset show 旅伴
/new 新剧情
```

编辑时发送 `/preset edit 名称` 并在下一行填写**完整的新正文**，整段仍作为一条消息发送。
`/preset delete 名称` 删除自己创建的公共模板；它不会删除任何用户的聊天记录或已入队任务。

预设仍保存在插件数据目录的 `presets/` 中，默认是 `data/presets/`，支持本地编辑 UTF-8 Markdown。
文件名就是选择名称。QQ 创建的文件首行注释记录创建者，本地编辑正文时保留该首行；该注释不发送给模型或 QQ。
没有创建者注释的本地模板公共可选，但只能在本机编辑或删除。
项目提供可编辑的角色模板 `examples/presets/角色扮演.md`；首次使用可复制到：

```bash
mkdir -p data/presets
cp examples/presets/角色扮演.md data/presets/角色扮演.md
```

重启 Koishi 加载本次功能后，在 QQ 私聊发送（群聊需 @ 机器人）：

```text
/mode 本地
/preset
/preset 角色扮演
你好，我们开始故事吧
/new 新剧情
```

- `/preset` 显示当前选择和公共预设列表；`/preset list 2` 翻到列表第二页。`/preset 名称` 切换，名称不带 `.md`，可含中文和空格。
- `/preset show` 查看当前预设，`/preset show 名称` 查看任意公共预设；长正文分页，`/preset show --page 2 名称` 查看第二页。
  列表和正文均标注「我创建」或公共/本地模板属性，不公开其他用户的 QQ 标识。`/preset off` 仅关闭当前会话选择，不删除模板。
- 每个会话独立保存预设名称，切换 `/chat` 和重启后仍保留；`/new` 沿用当前预设、模型和本地后端，开启空白聊天上下文。
  预设文件是整个实例的共享库，选择状态按所属用户、私聊/群聊及会话分别保存。
- QQ 或本地修改预设后，所有选择它的会话在下一条消息读最新内容，无需重启或 `/reload`。
  任务入队时保存正文和版本摘要，编辑、删除模板不会改变排队中或生成中的任务；处理中可管理自己的模板，但不能切换当前选择。
- 切换预设或 `off` 都保留已有聊天记录。更换角色需要空白剧情时，切换预设后再 `/new`。
  在网页后端也可先保存预设选择，仅在切到 LM Studio 后使用，预设不会发送到 ChatGPT 网页。
- 正文最多 8000 字，不能为空；名称最多 64 字，不可含路径字符，`show`、`off` 等保留名称不可作为预设名。
  只读取普通 `.md` 文件，不读取符号链接。选中的文件丢失或无效时明确报错，不会忽略预设继续生成。
- 每次本地请求都在历史前添加系统提示词，历史裁剪不会删除它。预设占用 `lmStudioHistoryChars` 字数预算；
  预设和本次消息已超过预算时不提交模型。字数预算不等于模型 token 容量，过长设定仍需结合模型上下文调整。

本地预设及任务里的预设快照随 `data/` 被 Git 忽略。自定义 `dataDir` 时，在实际数据目录的 `presets/` 编辑。
创建者身份依据 QQ 适配器提供的用户标识识别，私聊和不同群聊的标识可能不同；需使用创建时的 QQ 身份管理。
`npm run validate:lmstudio -- --presets` 使用临时公共预设和真实本地模型，验证 QQ 命令创建/管理、创建者权限、系统提示词、重启保存与 `/new` 继承，QQ 回传使用模拟发送。

## 怎么用

直接发消息就行。**没有触发词，也没有「画图」这类前缀**：私聊里发什么，ChatGPT 就收到什么。

- 发一段文字 → 原样送进 ChatGPT，回复原样回来。
- 发一张图片 → 作为附件送进 ChatGPT（可以只发图片，不写字）。
- 发「图片 + 文字」→ 文字是正文，图片是附件。
- 使用 QQ 的「引用回复」→ 被引用消息中的文字、图片与本次消息一起发送，分别标注「引用消息」和「本次消息」。群聊仍需 @ 机器人。
- **默认就在同一个网页会话里连续对话**。第一次发消息时会自动以用户名创建会话（无用户名时使用用户 ID），
  之后同一个用户的消息都进同一个 ChatGPT 会话，所以可以直接说「把刚才那张图改成蓝色的」，
  不需要任何命令，也不会每条消息都新开一个会话。
- 想换话题或清空上下文 → `/new 名字`（名称可省略，默认使用用户名；旧会话保留，可用 `/chat` 切回）。

群聊里需要 @ 机器人，见下面的「授权与群聊」。

### 管理命令

发送 `/help` 查看当前模式常用命令，`/help all` 查看完整清单。命令以 `/` 开头；普通的「取消」「stop」等文字仍作为聊天内容发送。
方括号中的参数可省略；任务默认选择当前会话最近一条，也可填写任务编号查询或取回历史回复。

| 命令 | 作用 |
| --- | --- |
| `/help [聊天\|工作\|本地\|all]` | 当前板块常用帮助；all 查看完整帮助 |
| `/mode [聊天\|工作\|本地] [模型编号]` | 切换模式，分别保留上下文；不带参数查看当前模式 |
| `/model [模型编号]` | 查看本机聊天模型；带编号选择并进入本地模式 |
| `/new [名称]` | 开启新对话，名称默认使用用户名，旧会话保留 |
| `/rename 新名称` | 重命名当前会话，最多 40 字；可先用 `/chat 编号` 切换到要修改的会话 |
| `/chat [会话编号]` | 列出会话；带编号切换 |
| `/backend [web\|lmstudio] [模型编号]` | 旧版兼容，日常请使用 `/mode` |
| `/skill [名称\|list\|show\|off]` | 查看、选择或关闭技能；聊天中选择会进入工作模式，本地选择独立保存 |
| `/preset [名称\|show\|list\|create\|edit\|delete\|off]` | 公共预设查看、选择或管理；编辑/删除限创建者；新会话沿用 |
| `/prompt [模板名\|list\|show\|preview\|create\|edit\|delete\|off]` | 查看、选择、预览或管理公共图片模板；编辑/删除限创建者 |
| `/draw 角色名` | 将当前模板替换角色名后发送到 GPT 网页生成图片 |
| `/close [会话编号]` | 关闭当前或指定会话，保留历史记录 |
| `/status [任务编号]` | 查看连接与任务状态；带编号查询指定任务 |
| `/stop [任务编号]` | 取消排队，或请求停止生成 |
| `/retry [任务编号]` | 重发已取回的回复，不重新生成 |
| `/logs [on\|off]` | 查看或切换过程通知 |
| `/reasoning [程度]` | 查看或切换当前会话的推理程度 |

会话名称修改后会保存，重启后仍保留，不影响聊天上下文；已有名称不会自动覆盖。这里的名称用于桥接会话列表与通知，不会同步修改 ChatGPT 网页侧的标题。

已移除最近任务列表和单独的重开命令；新建与重开统一用 `/new`，连接检查合入 `/status`。
旧的 `桥接…` 命令只提示使用 `/help`，不再执行操作，也不会提交网页任务。
仅完整匹配的文字命令会执行；含图片的消息、引用中的命令仍按普通内容转发；未知的斜杠命令返回帮助，不会提交模型。

同一个会话同一时间只处理一条消息：上一条还在跑的时候再发，会被直接拒绝并提示等待或取消。
如果绑定的网页会话被删除或链接失效，确认本条消息尚未提交时会自动新建网页会话并重试一次，无需重新输入。
新会话无法恢复旧历史；已提交或状态不明确时不自动重发。

并发 1，待完成任务最多 5，普通消息文字最多 1500 字；`/draw` 展开后的模板最多 8000 字。
默认接收后立即确认，运行 60 秒后最多提醒一次；回复完成后自动发回。
实际发送仍受 QQ 平台额度和消息审核约束。

### 只接收最终结果

发送 `/logs off`，即可关闭接收确认和自动进度提醒；
发送 `/logs on` 恢复。关闭后仍会发送最终回复、失败原因和必要的输入错误提示，
主动使用帮助、状态、取消等命令也会正常响应。

设置按「用户 + 当前私聊/群聊」分别保存到 `data/preferences.json`，重启后仍保留；
切换或新建网页会话不影响设置。群聊中只影响自己的请求，不会替其他成员关闭通知。
该开关控制机器人发给用户的过程消息，不关闭本机日志或任务记录。

### 切换网页推理与工作强度

发送 `/reasoning` 查看当前会话设置。聊天模式可用 `/reasoning high` 或 `/reasoning 高`。
工作模式按网页原生强度档位选择，例如 `/reasoning 2`；`instant` 选择最低档，`pro` 选择最高档，`default` 跟随网页。
工作档位可能同时切换模型与推理强度；数字以当前网页菜单为准，关闭并重新打开菜单确认后才提交。
同名“中”“轻度”可能对应不同模型，新版跨模型菜单请使用档位编号。下面的命名选项用于聊天模式：

| 参数 | 网页选项 |
| --- | --- |
| `instant` / `即时` | Instant，即时响应 |
| `medium` / `中` | Medium，标准思考 |
| `high` / `高` | High，扩展思考 |
| `xhigh` / `超高` | Extra High |
| `pro` | Pro |
| `default` / `默认` | 跟随网页当前选择，不强制切换 |

可用选项取决于账号套餐和模型，见 [OpenAI 官方说明](https://help.openai.com/en/articles/20001354-gpt-6-and-other-models-in-chatgpt)。
该命令操作网页的思考强度滑块，关闭并重新打开菜单确认选择后才提交消息，不向消息正文添加提示词，也不调用 API。

设置按当前会话的聊天/工作模式分别保存到 `data/conversations.json`，重启和 `/chat` 切回后保留；
`/new` 沿用两种模式的设置，首次使用时默认跟随网页。每条任务入队时记录推理程度，修改设置从下一条消息起生效，排队或生成中的任务不变。
网页选择可能影响账号后续默认值，因此 `default` 会沿用网页当前值；有明确设置的会话每次发送前都会重新应用并读回确认。

聊天模式中 Pro 选项暂时缺失（例如额度用尽）时，`pro` 任务改用滑块当前可用的最高档，关闭并重新打开菜单读回确认后才继续。
会话和任务请求仍保留 `pro`；后续任务重新检查菜单，Pro 恢复后自动使用 Pro。
任务的 `submission.json` 分别记录请求档位 `reasoningEffort`、实际档位 `reasoningApplied` 和降级原因 `reasoningFallback`。
无法识别滑块、其他程度不可用或切换未确认时，本条任务明确失败，不上传图片或提交消息。
更新后请**重启 Koishi 实例并重新加载 Chrome 扩展**；旧扩展不支持该功能时会提示重新加载。
`/chat` 显示各会话已设置的程度，`/status` 显示任务入队时的程度。

### 网页会话异常恢复（0.3.1）

回复中的可编辑写作块不会再被当成消息输入框。输入框短暂缺失或出现多个候选时先等待页面稳定；只有尚未填写/上传/提交、没有未知草稿或现有附件时，才允许刷新原专用标签页一次，保持同一会话上下文。

已开始上传或提交的任务不通过刷新、再次点击发送来恢复，避免重复消息。仍无法安全定位时，扩展保留故障页面和结构诊断；弹窗提供“查看最近故障网页”。更新后请在 Chrome 扩展管理页重新加载扩展。

### 网页已回复但没有回传（0.3.2）

扩展按本轮用户消息的位置读取后续所有回复块，支持“图片画廊 + 空的末尾回复块”，避免只读取最后一块而漏图。提交确认加入消息 ID，不再只依赖可能减少的可见历史数量。更新后需重新加载 Chrome 扩展；重启 Koishi 可启用新的提交诊断记录。

## 回复是怎么回传的

网页回复会被还原成**有序片段**：正文（保留标题、列表、引用、表格、链接与行内代码的结构）、
代码块（保留语言）和图片。发送时按这个顺序依次发出，**图片在回复里的位置不会丢**。

- ChatGPT 生成的 GIF 文件和 PNG/JPEG/WebP 图片文件也会作为图片回传 QQ；GIF 保留原始动画字节，
  不转换成静态 PNG。支持本轮回复中的文件链接及网页文件预览卡片，重复出现的同一文件只回传一次。
- 回复图片/文件合计最多 10 个，每个最多 20 MB；下载失败、文件过期或格式不符会明确失败。
  生成文件通过网页自身的图片预览或本域文件地址读取，不下载普通外部链接指向的文件。
- 若后续回复只有 `/mnt/data/文件名.gif` 等独立路径，0.3.12 会按文件名寻找同一网页会话中唯一对应的
  历史生成文件卡片并回传。找不到附件或存在同名版本时明确提示重新提供附件，不把路径当作成功的图片回复。
- GIF 和静态图随任务保存，发送中断后 `/retry` 可继续回传；旧 PNG 任务仍可重发。
  本次仅增加回复能力，上传文件的解析规则不变。更新到 0.3.12 后需重启 Koishi 并重新加载 Chrome 扩展。

- 代码块用 ``` 围栏原样发出，QQ 不渲染 Markdown，看到的就是纯文本。
- 单条文本超过 1500 字会按段落边界拆成多条；代码块拆分后重复围栏，超长单行也会拆分。
- 整条回复超过 6000 字会截断并明确提示，完整内容保留在本机任务目录的 `reply.md`；重发仍受同一长度上限限制。
- **模型的内容拒绝是正常回复**。「抱歉，我不能帮你做这个」会原样发给你，不会被当成失败丢掉。
  只有真正的技术问题（登录失效、额度受限、网页操作失败、超时）才报告为失败。

### 发送失败与恢复（0.3.0）

- 本机桥接短暂断线时保留网页任务并重试回传，不重复点击网页发送。
- 网页结果先写入 `result.json` 再确认接收；进程在更新任务状态前退出，重启后可恢复结果，用 `/retry` 取回。
- QQ 每确认一段就保存发送进度。发送中途失败后，`/retry` 从未确认的一段继续；已全部发送成功的任务则从头重发。
- QQ 超时或服务退出时，最后一段可能已送达但尚未记账；手动重发可能重复这一段，不能保证恰好发送一次。
- 排队耗尽回复窗口的消息不会再提交网页，会提示重新发送。

## 参考图片输入

引用回复支持适配器提供的引用文字和图片，只读取直接引用的那一条，不递归读取更早的引用。
引用图片排在本次上传图片之前，沿用相同的下载安全校验；两部分合计受图片数量、文字长度限制
（文字长度包括引用分隔标记）。引用中的命令仅作为上下文，不会执行。
如果 QQ 没有提供引用正文，或引用的只有不支持的文件/语音等内容，机器人会提示复制原文或重新发送原图，
不会仅凭引用编号猜测原内容。

发送图片（`img` 元素）时，图片作为附件送进 ChatGPT，文字作为正文。

- 一次最多 2 张参考图（可用 `maxInputImages` 调整）；图片上限默认 10 MB，可用 `maxInputBytes` 调整。
- 只接受 `http(s)`、`data:` 与 OneBot `base64://` 地址。`file://` 等本地路径一律拒绝，不会读取本机任意文件。
- 下载前解析域名并拒绝回环、内网、链路本地与保留地址（SSRF 防护），重定向逐跳重新校验，避免公网链接跳到内网。
- 只接受 PNG/JPEG/GIF/WebP，按文件头嗅探而非 `Content-Type`；SVG/HTML 一律拒绝。
- 下载文件以 0600 写入临时目录，入队时移入任务目录并记录为 `input-<序号>.<扩展名>`，随任务一并持久化。
- 图片字节只在本机 5141 端口按任务令牌提供，不写入扩展的持久存储，也不出现在 QQ 消息里。

**一个诚实的限制**：ChatGPT 的输入框把图片当作附件，不是正文的一部分。
所以「图片夹在两句文字之间」这种位置关系无法表达 —— 文字顺序和图片顺序各自不变，但二者交错的相对位置会丢。

## 授权与群聊

默认仅允许 `allowedUsers` 中配置的 QQ openid 在私聊调用；将其设为 `["*"]` 可允许所有 QQ 私聊用户。

**群聊默认完全不响应**，必须显式设置 `groupChat: true` 才启用。启用后群里**任何成员** @ 机器人都可使用，
`allowedUsers` 不参与群聊判定（群里的 QQ openid 是群作用域 id，与私聊名单不是同一套），
回复直接发到群里，群成员均可见。群聊里 `@` 是硬性前提：Koishi 不会把未被 @ 的群消息交给本插件，
私聊则无需 @。每个成员在同一群里拥有各自独立的会话，互相看不到也切不进对方的会话。

群聊时请输入 `@`，从 QQ 弹出的列表中选择机器人，再输入 `/help` 等命令发送。
复制后仅剩普通文字的 `@昵称` 不带提及信息，不会触发群 @ 事件；当前官方 QQ 连接方式可能根本收不到这条消息。
需要复用命令时，只复制命令正文，重新选择一次机器人。私聊可直接发送 `/help`。

> 注意：一旦开启群聊，群里任何人都能消耗你账号的 ChatGPT 网页额度。

## 安装与配置

浏览器扩展支持 macOS / Windows 上的 Chrome 120+。Koishi 和 Chrome 须运行在同一台电脑，
需要 Koishi `^4.18.0`、Node 20+，建议 Node 22 LTS 或更高版本。macOS 不需要 `sips`、AppleScript 或按键权限；图片处理和网页操作使用 JavaScript 与 Chrome 扩展 API。

在 Koishi 插件市场搜索 `chatgpt-bridge` 安装，包名为 `koishi-plugin-chatgpt-bridge`。
新版本收录可能延迟；独立 npm 实例也可按 [安装说明](installation.md) 从 npm 安装。
在插件配置表单中填写 `allowedUsers`，确认 QQ 适配器已连接，再启用插件。

网页模式还需在 **Koishi 实例目录**运行：

```bash
npx --no-install koishi-gpt-bridge-setup
```

命令会把完整扩展导出到实际数据目录的 `browser-extension/`，复用本机桥接令牌，
不修改 npm 包目录，也不复制开发机器的 `config.js`。随后在 `chrome://extensions` 开启开发者模式，
加载命令输出的目录，并登录 ChatGPT。插件和扩展版本应均为 `0.4.3`。

```bash
npx --no-install koishi-gpt-bridge-doctor
```

新安装默认数据目录为 `<Koishi 实例>/data/codex-image-local/`。自定义目录或端口时，生成命令须传入同一配置：

```bash
npx --no-install koishi-gpt-bridge-setup --data-dir "/实际路径/Koishi 数据目录" --port 5141
npx --no-install koishi-gpt-bridge-doctor "/实际路径/Koishi 数据目录"
```

Windows 路径同样需要加引号。端口未指定时优先读取运行中插件的端口记录，无记录时使用 5141。
“令牌不匹配”表示配置与运行中 Koishi 的数据目录不一致。

旧版源码链接部署检测到项目 `data/` 时继续使用原目录。**切换为 npm 安装前，须显式配置原数据目录的绝对路径，
或先停止实例并按 [迁移步骤](installation.md#旧版源码链接部署升级) 复制完整数据。** 不会自动合并新旧记录。
原 `node scripts/setup-web-bridge.cjs [端口] [dataDir]` 保留给旧版源码部署，仍在源码的扩展目录写入配置。
新源码部署请使用 `npm run setup:extension -- --instance-dir "<Koishi 实例目录>"`。

新安装使用配置键 `chatgpt-bridge`。从旧版源码链接切换时，将 `koishi.yml` 中的
`codex-image-local` 键改为 `chatgpt-bridge`，保留配置值和实例后缀；按上面的迁移步骤显式指定数据目录。

必需配置只有一项：

- `allowedUsers`：允许在**私聊**调用本插件的 QQ openid 列表，`["*"]` 表示所有 QQ 私聊用户。

可选配置：

- `groupChat`：设为 `true` 才响应群聊。默认 `false`，即群聊完全不响应。启用后群里任何成员 @ 机器人即可使用，结果直接发到群里；`allowedUsers` 不参与群聊判定。
- `notifyProgress`：过程通知默认值，默认 `true`；设为 `false` 后，没有个人设置的用户只接收最终回复或失败原因。用户通过 `/logs` 保存的设置优先。
- `webBridgePort`：本机桥接端口，默认 5141。
- `maxTextChars`：单条消息的文字上限，也是单条回复的拆分长度，默认 1500。
- `maxReplyChars`：一条回复回传到 QQ 的总文字上限，默认 6000，超出会截断并提示。
- `maxInputImages`：单条消息可携带的参考图数量，默认 2。
- `maxInputBytes`：单张参考图体积上限，默认 10 MB。
- `replyTimeoutMs`：等待网页回复的超时上限，默认 5 分钟。实际还受 QQ 回复窗口约束：从收到消息起最多约 270 秒进入停止流程，另留最多 15 秒确认停止及发送失败原因；下载和排队也计入窗口。
- `sendTimeoutMs`：每次 QQ 发送等待确认的时间，默认 20000 毫秒；超时记录为送达不确定，避免无限卡住队列。
- `mediaSendTimeoutMs`：QQ 图片/GIF 上传与发送确认的等待时间，默认至少 60000 毫秒；未指定时也不会低于
  `sendTimeoutMs`。媒体消息仍需平台返回发送确认才记为成功。
- `retentionDays`：默认不设置＝永久保留。设为大于 0 的天数后，已结束（完成/失败/取消/中断）的任务超过该天数会在启动时及每 6 小时整体删除，回收参考图与结果图占用的空间。排队中和运行中的任务永不会被清理。

停用插件后其正在执行的任务会被取消。

部署细节、重启方式与排障见 [docs/operations.md](operations.md)。

## 项目结构

```text
src/
├── index.cjs          装配与 Koishi 绑定
├── commands/          一份注册表负责路由、参数和按模式帮助
│   ├── modes.cjs      /mode、/model、推理设置与旧命令兼容
│   ├── sessions.cjs   新建、选择、重命名、关闭话题
│   └── …              技能、预设、模板命令
├── app/               用例编排
│   ├── bot.cjs        入站、任务、状态、通知与发送
│   ├── engines.cjs    按任务快照选择网页或本地执行
│   └── session-scope.cjs  授权、聊天范围、默认名称
├── core/              模式、会话、队列与资源库领域规则
├── bridge/            网页、本地模型、QQ 回传适配器
└── lib/               下载、回复与原子文件工具
browser-extension/     页面操作与任务状态机；Chat/Work 共用
scripts/               诊断、静态检查、隔离实测工具
test/                  领域、应用、桥接、扩展及架构回归
docs/                  设计、运维、版本与验收记录
data/                  私有运行状态，已 gitignore
```

依赖方向为 `commands → app → bridge → core → lib`，入口只做装配；命令也可直接调用领域接口。
架构测试会检查反向依赖、循环依赖、孤立模块和命令直接访问传输适配器。
详见 [架构](https://github.com/Mlnikko/Koishi-GPT-Bridge/blob/main/docs/architecture.md) 与 [三模式设计](three-modes.md)。

## 验证

```bash
npm ci --ignore-scripts # 源码开发时安装配置表单所需的 Koishi
npm run check     # 检查脚本语法、入口、插件与扩展版本一致
npm run benchmark:queue # 1 万条任务的内存查询对照基准，不包含模型或网络耗时
npm test          # 发现全部嵌套 .test.cjs 文件并运行
npm run check:package # 打包并在隔离 Koishi 实例验证发行包
npm run doctor    # 检查运行中的实例；自定义目录：npm run doctor -- "/实际/dataDir"
```

覆盖消息片段化与顺序、回复序列化与拆分、去重、串行取消、重启、参考图下载边界、桥接鉴权与协议校验、
扩展提交顺序与回合识别，以及分层与依赖规则的守卫。
测试启动器显式传入文件路径，不依赖 shell 或 Node 的 glob 展开。

真实网页与真实 QQ 收发需要分别验证，单元测试不替代端到端验收；已完成的验收记录见 [docs/history.md](https://github.com/Mlnikko/Koishi-GPT-Bridge/blob/main/docs/history.md)。
