# 架构

## 分层与依赖方向

运行时模块按依赖方向分三层，箭头只能自上而下：

```
index.cjs            插件入口，可用全部
   │
   ├── bridge/       传输层：与 Chrome 扩展的本机 HTTP 桥接
   │      │
   ├── core/         领域层：会话、队列、语义
   │      │
   └── lib/          通用工具层：不依赖项目内任何模块
```

| 分层 | 允许依赖 | 模块 |
| --- | --- | --- |
| `src/lib/` | 仅同层 | `image.cjs`、`feedback.cjs` |
| `src/core/` | `lib`、同层 | `conversations.cjs`、`queue.cjs`、`intent.cjs`、`natural.cjs` |
| `src/bridge/` | `lib`、`core`、同层 | `web-bridge.cjs` |
| `src/index.cjs` | 全部 | 入口 |

`test/architecture.test.cjs` 会把这张表变成可执行约束，检查四件事：

1. 每个运行时模块都归属已知分层——新增目录时该测试会失败，提醒更新分层表，而不是让规则静默失效。
2. 依赖方向只能自上而下，出现反向依赖即失败。
3. 没有从入口不可达的孤立模块（防重构后留下死代码）。
4. 运行时模块不含 `child_process`、`execFile`、`codexPath`、`CODEX_HOME`、`runner.cjs`。

第 4 条是防止本地 CLI 调用路径回归的哨兵。生图与语义分类全部经由浏览器内的在线页面完成，一旦有人重新引入
本地子进程，就必须同时重新处理「不继承 Koishi 密钥」与「Windows 无进程组信号」两件事。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `src/index.cjs` | Koishi 插件入口。校验配置、装配各模块、注册图片中间件与全部命令、维护任务与 QQ 会话的映射、把结果发回 QQ。 |
| `src/lib/image.cjs` | 参考图安全下载（协议白名单、SSRF 防护、体积与超时限制、文件头嗅探）与 PNG 文件头解析；QQ 消息元素的图片/文字归一化。 |
| `src/lib/feedback.cjs` | 面向用户的文案生成、失败原因分类、本机路径与凭据脱敏、模型文本转义。 |
| `src/core/conversations.cjs` | 画图会话的持久化（名称、归属用户、选中状态、绑定的 ChatGPT 会话编号 `webThreadId`）。 |
| `src/core/queue.cjs` | 任务队列的持久化与串行执行；参考图从暂存目录移入任务目录；终态任务的保留期清理。 |
| `src/core/intent.cjs` | 语义词表、本地规则判定、分类提示词与分类结果校验。**纯数据与纯函数，不发起任何网络或进程调用。** |
| `src/core/natural.cjs` | 自然语言路由：规则优先，必要时调用注入的分类器，再把意图映射到已有命令处理函数。 |
| `src/bridge/web-bridge.cjs` | 本机 HTTP 桥接服务（默认 127.0.0.1:5141）。管理当前网页任务、令牌校验、进度与结果回传、参考图字节按需下发。 |

## 状态落盘

| 路径 | 内容 |
| --- | --- |
| `data/conversations.json` | 会话名称、所属用户、选中状态及 ChatGPT 会话编号。 |
| `data/jobs/<id>/job.json` | 任务状态、提示词、参考图元数据、ChatGPT 会话编号。 |
| `data/jobs/<id>/result.png` | 完成的图片。 |
| `data/jobs/<id>/input-<序号>.<扩展名>` | 该任务下载的参考图片。 |
| `data/jobs/<id>/failure.json` | 失败详情（仅在失败时产生）。 |
| `data/intent-receipts.json` | 自然语言消息去重收据。 |
| `data/web-bridge-token` | 扩展与桥接共用的随机令牌。 |

任务文件含提示词和 QQ openid，权限 0600，目录权限 0700。`data/` 已在 `.gitignore` 中忽略。

## 数据流

### 文本提示词

```
QQ 私聊消息
  → index.cjs 命令/自然语言路由
  → queue.enqueue 落盘 job.json（kind: text）
  → web-bridge 挂起一个待领取任务
  → Chrome 扩展轮询 /state 领取
  → 扩展在专用标签页填写并提交 ChatGPT
  → 扩展读回图片像素，POST /result
  → 保存为 result.png，状态置 ready
  → 回传 QQ；超出消息窗口时改为「取图」取回
```

### 参考图片

```
QQ 私聊消息（含 img 元素）
  → image.messageImages 取出图片地址
  → image.downloadImage 安全下载到系统临时目录（0600）
  → queue.enqueue 移入任务目录并记录 inputImages（kind: image）
  → 扩展在 /state 看到 images 元数据
  → 扩展后台线程按令牌从 GET /input 取回字节（页面 CSP 不允许页面脚本直连本机）
  → 转成 File 注入文件选择器，派发 input/change
  → 确认输入框已出现附件后才填写文字并提交
  → 同文本链路回传
```

参考图链路的失败是**闭环**的：45 秒内无法确认附件就明确失败，绝不退化成纯文字请求，避免生成与参考图无关的图片。
下载阶段失败则直接回复「图片处理失败」并且不入队。

## 失败反馈

保存并返回网页最后一条回复，区分明确拒绝、工具不可用、认证失败、额度限制、网络失败与无明确原因的缺图。
缺图本身不等于审查。异常写入任务目录 `failure.json`；任务状态与取图指令都可查询原因。
模型文本作为纯文本转义，隐藏常见凭据、服务 URL 与本机路径（含 Windows 盘符与 UNC 路径）。
不会为拒绝或错误自动重试生成。

取消只是请求网页停止生成，是否真正停下取决于浏览器状态，也不保证远端计算立即停止或返还额度。
服务重启后进行中的任务标记 interrupted，不自动重复生成；当前没有执行中任务恢复，也没有自动重试生成，避免重复消耗。

## 多会话行为

会话按 QQ 用户与私聊隔离，最多 20 个打开会话。会话编号为 8 位，任务编号为 12 位；命令分别使用对应编号。
每个会话同一时间仅允许一个待完成任务，不同会话共用全局串行队列。切换会话不会改变已排队任务的归属。
关闭会话前须等待或取消任务；关闭不会删除历史任务和图片。重启后保留会话选择，但不会自动重试中断任务。

续画通过服务器保存的确切 ChatGPT 会话编号进入同一网页会话，不接受用户提交任意会话编号。
续画只接收本轮新回复中的图片；未产生新图片时保留真实错误，不回传旧图。
当前会话之外的历史任务仍可用明确任务编号查询或取图。

## 自然语言识别

默认启用，仅处理允许用户的 QQ 私聊纯文本；原有明确命令优先。

- 简单的肯定绘图请求、查询、取消、取图由本地规则处理，不联网。
- 绘图与改图请求（`directImage`）直接交给 ChatGPT，由它自己理解语义并生图，不额外分类。
- 其余消息（会话管理、有歧义的表达）由**同一个已登录的 ChatGPT 网页**分类：桥接打开一个专用标签页，
  用结构化输出返回意图 JSON，再由程序调用已有命令处理函数。绝不执行模型生成的命令字符串。

示例：

- `我想画一个芙兰朵露。` → 直接绘图，不分类。
- `让刚才那张图里的背景变成夜晚，其他都保留` → 当前会话续画；需已选中会话且已有图片。
- `刚才那张画好了吗？` → 查询任务。
- `不用画了` → 取消当前会话最近任务。
- `另开一段绘图对话，名字就叫月夜` → 新建并切换。
- `我不想画芙兰朵露了，停止当前任务` → 取消，不会误当绘图。

非命令文本的分类请求附带的上下文只含该用户当前私聊的会话名称、任务编号与状态；不提供其他用户记录或 QQ 凭据。
分类超时 60 秒，且与绘图任务共用同一个桥接槽位——绘图进行中时分类会返回“网页正在处理其他任务”，此时仍可使用明确命令。
新命令会使旧识别结果失效，避免识别完成后误操作已切换的会话。歧义或多项操作要求用户重新明确表达；
普通聊天不触发生图，也不作为通用聊天机器人回复。

消息去重收据保存在 `data/intent-receipts.json`（最近 24 小时、最多 1000 条）；未完成的识别在重启后不会自动重放。
识别失败保留明确命令入口，可重新发送消息重试。

## ChatGPT 网页生图连接器

`src/bridge/web-bridge.cjs` 为本机网页任务服务，`browser-extension/` 为 Chrome 扩展。
它操作已登录的 `https://chatgpt.com/` 普通 Chat 页面，通过页面输入框提交请求，从本轮生成图片读取像素并保存为 PNG，
不调用未公开聊天接口，也不复制登录 Cookie。

网页无法连接时明确失败，不会回退到其他方式生图。扩展更新后在 Chrome 扩展管理页点击刷新。

扩展为绘图任务打开专用标签页。绘图期间不要编辑、刷新或关闭该页。任务与网页会话编号绑定；
续画仅进入该用户保存的网页会话，并只接收本轮新回复中的图片。无法确认提交时不会自动再次点击，避免重复生图。
页面验证需用户手动完成，连接器不会处理验证挑战。关闭 Chrome、登录失效、网页变化或额度不足均可能导致失败，可查看具体反馈。

带参考图片的任务多一个“上传”阶段：`/state` 只返回图片元数据，扩展在后台服务工作线程按任务令牌从 `GET /input`
取回字节（页面 CSP 不允许页面脚本直连本机），转成 `File` 注入 ChatGPT 输入框的文件选择器并派发 `input`/`change`。
确认输入框内已出现附件后才填写文字并提交；45 秒内无法确认附件则明确失败，绝不退化成纯文字请求，避免生成与参考图无关的图片。
上传只尝试一次，不会重复附加。

如果上次浏览器或 Koishi 在提交前退出，输入框可能留下带有 `QQ绘图任务 <任务编号>` 的连接器草稿。
扩展只会自动清理这种带有本连接器标记的旧草稿；检测到其他文本时会停止并提示用户手动处理，避免覆盖用户自己的输入。
