# 三种模式：设计、升级与验收

0.4.0 将产品模式与连接方式分开。聊天和工作使用同一个网页桥接器，本地模型使用 LM Studio；三者复用入站、排队、停止、任务持久化、状态与 QQ 回传。

## 使用方式

| 需求 | 操作 |
| --- | --- |
| 普通聊天 | 默认直接发消息，或 `/mode 聊天` |
| 工作能力 | `/mode 工作`，然后直接描述任务 |
| 网页原生技能 | `/skill 名称`，下一条消息起自动选择原生 @技能；从聊天模式选择会进入工作模式 |
| 本机模型 | `/mode 本地`；多个模型时 `/model` 查看、`/model 编号` 选择 |
| 新话题 | `/new [名称]`；沿用设置，各模式历史重新开始，旧话题保留 |
| 切回旧话题 | `/chat` 查看，`/chat 编号` 选择 |
| 状态与停止 | `/status`、`/stop`；重发已有结果用 `/retry [任务编号]` |
| 帮助 | `/help` 显示公共命令及当前模式操作；`/help all` 查看进阶管理 |

Chat/Work 能力以网页实际提供的功能为准。当前桥接支持文字、图片、引用及回复媒体，尚不支持任意网页控件、文档附件或全部 Work 功能。
本地模式支持文本和视觉模型输入，返回文字；本机 `SKILL.md` 在该模式下作为系统规则，不能凭此获得工具执行能力。
工作与本地分别保存技能选择，聊天模式不会加载技能正文或创建技能标记。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `src/index.cjs` | 构造模块，绑定 Koishi 中间件和生命周期 | 具体命令、模式执行、网页操作 |
| `src/commands/` | 路由、参数校验、分组帮助、管理用例 | 直接访问网页或模型连接器 |
| `src/app/bot.cjs` | 入站准备、配置快照、任务与通知、模式切换 | 页面 DOM 或模型 HTTP 协议 |
| `src/app/engines.cjs` | 按模式路由、截止时间、模式所属的网页绑定 | 命令解析、技能库发现 |
| `src/core/` | 模式定义、会话、队列、资源库和原子领域变更 | QQ、浏览器和模型 SDK |
| `src/bridge/` | 网页协议、本地 HTTP、QQ 发送确认 | 当前话题选择、命令路由 |
| `src/lib/` | 下载、片段、媒体与原子文件工具 | 上层业务依赖 |

模式定义统一放在 `core/modes.cjs`，包含产品名称、别名、传输方式及技能能力。
命令定义、参数形式和帮助共用一份注册表。没有为三个模式复制插件入口、队列、技能库或 QQ 发送器。
架构测试约束依赖方向、循环依赖、孤立模块和命令直接访问适配器，避免拆文件后继续相互耦合。

## 上下文和并发规则

一个桥接话题包含三个上下文：

```js
{
  id, owner, chat, name, mode: 'chat',
  contexts: {
    chat:  { webThreadId, reasoningEffort },
    work:  { webThreadId, reasoningEffort, skill },
    local: { model, preset, skill }
  }
}
```

聊天与工作绑定不同的网页会话，禁止绑定同一个 thread。两种模式各自保存推理程度。
本地历史继续按服务地址、用户、聊天位置、桥接话题和模型编号区分，更换模型不会拼接旧模型历史。
同一话题切换模式会恢复该模式历史；`/new` 只继承设置，不继承网页绑定，新的话题编号也会形成新的本地历史。

消息接收后冻结模式、模型、技能及预设快照。图片下载、排队和生成期间禁止切换模式或技能。
异步查询本地模型期间，若话题、模式或设置已变化，则拒绝应用旧查询结果。
运行时再次校验任务模式及本地模型。网页上传、填写和最终发送都会检查目标模式与会话，避免填写后被切换导致误发。

任务中的 `mode` 为显式字段；旧任务根据 `backend` 和 `skill` 推断模式。任务负载版本仍为 2，旧结果、图片及重发游标保持可读。
工作任务要求扩展声明 `web-modes` 能力，技能任务另需 `native-skills`；旧扩展领取前会得到升级提示，不会误发到聊天模式。

## 升级与回退

1. 空闲时重启 Koishi 加载插件 0.4.0，在 Chrome 扩展页重新加载 0.4.0。
2. 会话只读加载时在内存转换，首次成功修改前保存原文件到 `conversations.json.v1-<摘要>.bak`，再原子发布 version 2。
3. 旧网页话题有技能时归入工作模式，无技能时归入聊天模式；旧本地模式保持当前选择。已有网页绑定归入相应网页上下文。
4. 旧本地模型、预设、图片历史及话题编号保留。旧技能选择复制到工作和本地设置，后续分别修改。
5. 保存失败时不发布内存变更。遇到高于支持版本的数据会拒绝加载，不覆盖原文件。

回退时先停止实例，保存升级后的新数据，再用原始备份恢复 `conversations.json`，恢复旧源码和扩展后启动。备份只能恢复升级前的选择及绑定；升级后产生的任务仍保留，不能把回退理解为保留全部新上下文。
本次修改前的源码快照和实例验收记录保存在本机忽略的 `data/refactor-baselines/` 与 `data/acceptance/`，不包含公开配置中的凭据。

## 验收边界

自动化覆盖旧格式迁移和备份、写盘失败、三模式路由、各自历史及重启恢复、聊天不加载技能、无技能工作任务、图片准备期切换、模式帮助及授权、旧扩展能力校验、发送前模式和会话变化，以及已有媒体、取消和重发回归。

真实模型/网页生成与真实 QQ 送达分别记录。当前本机 31B 模型曾被 LM Studio 的内存保护拒绝加载；这种情况下明确反馈内存不足，不绕过保护、不保存虚构回复，也不自动重试。
本轮现场结果见 [验证与变更记录](history.md)。
